# MVP

## MVP statement

A person with no programming knowledge can create a simple Slay the Spire 2 character offline, use local artwork, export the complete project as one file, send it to a friend, and the friend can import it and play it.

## Required MVP capabilities

Subject to runtime feasibility:

- local project creation
- character identity/basic stats
- basic cards
- card upgrades
- a small but useful effect set
- at least one custom mechanic/status
- at least one relic
- starting deck
- local PNG artwork
- immediate validation
- autosave
- undo/redo
- portable project export/import
- local play/deploy flow
- actionable runtime errors

## Explicitly not MVP

Do not add these merely because they sound useful:

- accounts
- cloud storage
- mandatory telemetry
- AI generation
- real-time collaboration
- arbitrary external C# import
- Steam Workshop publishing
- every STS2 mechanic
- advanced animation authoring
- large-scale balance AI
- marketplace/community backend
- browser-hosted editor parity

## MVP quality bar

MVP is not complete merely because the features exist.

The normal path must be understandable without requiring the user to know:

- C#
- Godot
- BaseLib
- DLLs
- PCK packaging
- project schemas
- internal IDs
- Steam mod folder layout

## Current pre-MVP gate

Before implementation of the product MVP, Phase 0 must prove or reject the data-driven runtime approach.
